# Explainable LLM Agent — верность объяснений агентных решений

Демо тезиса «правдоподобное объяснение ≠ верное», применённого к **LLM-агенту**:
агент решает задачу через вызовы инструментов, а мы измеряем, врёт ли он, когда
объясняет, *почему* пришёл к ответу — сверяя объяснение не со SHAP, а с **реальным
следом выполнения** (трассой). Сиблинг проекта `explainable-ai`.

Полный замысел и принятые решения — в [docs/design-sketch-ru.md](docs/design-sketch-ru.md).

## Идея в двух абзацах

LLM-агент инструментирован так, что **каждый его шаг пишется неизменяемо** (трасса —
эталон правды, §3). Затем одна и та же модель объясняет ответ в двух режимах,
различающихся только входом (§4):

- **blind** — трассу не видит, вынужден правдоподобно рационализировать;
- **grounded** — видит трассу и обязан объяснять только по ней.

Сервис `audit` детерминированно (без LLM-судьи) сверяет каждое объяснение с трассой
и ставит балл верности: покрытие шагов, точность, обоснованность источников и
причинная валидность (абляцией). CI-guard требует разрыв `grounded − blind ≥ порога`.

## Сервисы (эскиз §6)

| Сервис | Порт | Роль |
|---|---|---|
| `gateway` | 12100 | оркестрация + UI трёх зон, `eval`/CI-guard |
| `agent-runtime` | 12101 | выполняет агента, пишет трассу; fixture-режим инструментов |
| `narrator` | 12102 | два режима объяснителя (blind/grounded) |
| `audit` | 12103 | метрика верности над трассой, абляционные перезапуски |

## Запуск

```bash
make up      # fixture-режим (офлайн, без ключа)
make eval    # прогон демо-задач, разрыв верности; код 1 при gap < порога
```

LLM (агент и нарратор) — одна модель `moonshotai/kimi-k2` через OpenRouter, как в
сиблинге (§12.6). Live-режим требует `OPENROUTER_API_KEY`; по умолчанию всё работает
из fixtures.

## Статус — все фазы готовы

- **Фаза 0:** каркас — контракты `shared/`, compose/CI/Makefile, реестр инструментов.
- **Фаза 1:** `agent-runtime` — свой tool-раннер, запись трассы, fixture-абляция (§3, §12.1–12.4).
- **Фаза 2:** `narrator` blind/grounded, одна модель, различие только во входе (§4).
- **Фаза 3:** метрика верности, компоненты 1–3 + fabrication_rate (§4).
- **Фаза 4:** `causal_validity` через абляционный перезапуск agent-runtime (§5, §12.3).
- **Фаза 5:** gateway — оркестрация цепочки, UI трёх зон, `eval`/CI-guard (§8).

Прогон `make eval` (fixture, офлайн): разрыв grounded−blind = **65–69 баллов** при пороге 25.
